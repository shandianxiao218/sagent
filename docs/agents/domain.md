# 领域文档规则

本文件说明工程 skills 在探索本仓库时如何读取领域文档。

## 布局

本仓库采用 single-context 布局。

预期文档位置：

- 根目录 `CONTEXT.md`：项目领域语言、核心概念、业务规则、术语表。
- `docs/adr/`：架构决策记录。

## 开始工作前读取

在实现、诊断、重构或拆 issue 前，优先读取：

1. 根目录 `CONTEXT.md`
2. 与当前任务相关的 `docs/adr/` 文档
3. 与当前需求相关的 issue 正文和评论

如果这些文件不存在，静默继续，不要因为缺失而阻塞任务。`/grill-with-docs` 等生产类 skill 会在术语和决策真正明确后再补充这些文档。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-example-decision.md
└── src/
```

## 使用项目术语

输出 issue 标题、实现计划、测试名、重构建议时，应使用 `CONTEXT.md` 中定义的领域术语，不要随意替换同义词。

如果需要的概念不在术语表中，说明可能存在两种情况：

1. 正在发明项目并未使用的新语言，应重新考虑。
2. 项目确实缺少一个领域概念，应记录给 `/grill-with-docs` 后续补充。

## ADR 冲突处理

如果某个实现建议和已有 ADR 冲突，必须显式指出，而不是静默覆盖：

> 与 ADR-0007 冲突，但值得重新讨论，因为……
